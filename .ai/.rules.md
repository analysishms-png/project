# Analysis HMS — Development Rules (0-Bug Policy)

> **Purpose**: Ye rules kisi bhi new implementation / feature / bug-fix ko **0 bugs ke saath** deliver karne ke liye hain. Ye project ke verified analysis (`.ai/ANALYSIS_REPORT.md`), 2026 research (`.ai/RESEARCH.md`), security data (`.ai/SECURITY.md`), aur upgrade roadmap (`.ai/UPGRADE_PLAN.md`) se derived hain.
>
> **Applies to**: Har developer aur har AI agent jo is codebase mein code likhta hai.

---

## 1. Golden Rules (Sabse Pehle)

1. **Read before edit** — change karne se pehle related controller, model, migration, view, route, business logic padho. Kabhi guess mat karo.
2. **Understand business logic** — hotel workflow (reservation → check-in → billing → night audit) kabhi mat todo. Har change business impact samjho.
3. **Never break backward compatibility** — existing routes, URLs, function names, DB columns change mat karo without explicit permission.
4. **Never remove functionality** — sirf explicitly requested cheez hi remove karo.
5. **Fix root cause, not symptom** — error ka root cause find karo, patch blindly mat lagao.
6. **No destructive SQL without confirmation** — `DROP`, `TRUNCATE`, `DELETE` without `WHERE`, `ALTER` with data loss = BANNED without user approval.
7. **Test before finishing** — bina test ke code complete nahi mana jaata.
8. **Document + update memory** — har change ke baad `.ai/CHANGELOG.md` aur relevant `.ai/` files update karna MANDATORY hai (auto-memory system).

## 2. Mandatory Workflow (Har Task Mein)

```
ANALYZE → PLAN → IMPLEMENT → TEST → REVIEW → DOCUMENT → UPDATE MEMORY
```

| Step | Requirement |
|------|-------------|

## 3. PHP / Laravel Coding Rules (Project-Convention Based)

1. **Models**: Har model mein `protected $fillable` HONA CHAHIYE — mass assignment se bachao. `$guarded = []` kabhi use mat karo. (Verified: project ke saare 162 models `$fillable` use karte hain — isi pattern ko follow karo.)
2. **Helpers**: Naye helper function ko `if (!function_exists('name')) { ... }` guard mein wrap karo (existing pattern, see `app/Helpers/Helpers.php`). Naye helper file ko `composer.json` autoload `files` mein add karna mat bhoolo.
3. **Validation**: User input ko hamesha validate karo — `Validator::make()` ya Form Request use karo. Controller mein bina validation ke `create`/`update` call mat karo.
4. **Mass assignment**: `Model::create($request->all())` kabhi nahi — pehle `$request->validate()`, phir sirf whitelisted fields pass karo.
5. **Named routes**: Routes ko name do (`->name('module.action')`), URLs hardcode mat karo.
6. **Dependency Injection**: `app()` / `resolve()` ke bajaye constructor/method DI use karo.
7. **No debug leftovers**: `dd()`, `dump()`, `var_dump()`, `print_r()` (uncommented), `Log::debug` bulk — commit karne se pehle remove karo.
8. **No dead code**: Commented-out blocks mat chhodo; unused imports remove karo.
9. **Don't repeat yourself**: Duplicate logic service/helper mein extract karo. `Reporting.php` / `CheckRegister.php` ke duplicate `DB::raw CASE` blocks — naye code mein repeat mat karo.
10. **Avoid god controllers**: Bade controller (`CompanyController` = 22K lines) mein naya feature mat dalo — naya controller/service/class banao.
11. **Error handling**: Bina try-catch / proper response ke raw exception mat chhodo. User ko friendly error, log ko full detail.

## 4. Database Rules (MySQL)

1. **Column existence verify karo** — har query se pehle table/column ka naam verify karo (schema `.ai/database.md` mein documented hai). Typo = runtime error.
2. **Query Builder / Eloquent use karo** — raw SQL sirf tab jab business requirement ho (complex reports).
3. **Raw SQL mein input bind karo** — `DB::raw("...'{$var}'...")` = BANNED. Use parameter binding:
   ```php
   // ❌ NEVER
   DB::select("SELECT * FROM x WHERE code = '{$userInput}'");
   // ✅ ALWAYS
   DB::select("SELECT * FROM x WHERE code = ?", [$userInput]);
   ```
   Dynamic identifiers (table/column names) ko sirf hardcoded whitelist se allow karo.
4. **Collation**: Naye tables/columns hamesha `utf8mb4_unicode_ci` (ya consistent with project) — `COLLATE` workarounds (HouseKeeping wale) mat banao; root schema sahi karo.
5. **Indexes**: `WHERE`/`JOIN`/`ORDER BY` columns par indexes add karo, especially `(propertyid, vdate)`, `(paycode, propertyid)`, `(roomno, propertyid)` patterns.
6. **Destructive ops**: `DROP`/`TRUNCATE`/`DELETE` without WHERE → user confirmation zaroori.
7. **Migrations**: DB change hamesha migration se (`database/migrations/`), direct SQL se nahi.

## 5. Security Rules (OWASP — verified findings se)

1. **XSS — kabhi `{!! !!}` user input par nahi**:
   - `{{ $var }}` use karo (auto-escape).
   - Rich text zaroori ho to HTMLPurifier jaise sanitizer se hi `{!! !!}`.
   - ⚠️ Existing violation (fix karna hai): `{!! $ticket->problem !!}` in `tools/tickets.blade.php`, `admin/tools/tickets.blade.php`, `property/mytickets.blade.php`.
2. **SQL Injection** — section 4.3 follow karo. `whereRaw`/`selectRaw` mein hamesha `?` bindings.
3. **CSRF** — saare POST/PUT/PATCH/DELETE forms mein `@csrf`; `VerifyCsrfToken` middleware ko mat disable karo (sirf public APIs ke liye whitelist).
4. **Mass Assignment** — section 3.1 follow karo.
5. **File uploads** — validate (mimes, size), storage private, access via auth route. `chmod 777` kabhi use mat karo (project violation SEC-08: `MainController.php:984`).
6. **Sensitive data logging** — passwords, tokens, PII ko `Log::info` mein mat dalo.
7. **Secrets** — config/`composer.json`/code mein credentials hardcode mat karo; hamesha `env()`.
8. **Auth/Authorization** — sensitive routes par middleware (`auth`, `company`, `staff`, `superadmin`, `user`, `ApiAuth`) lagana na bhoolo. Route par auth check required hai jahan financial/guest data ho.
9. **Dependencies** — `composer update` ke baad hamesha `composer audit` chalao. Naya package add karne se pehle status check karo (abandoned packages avoid — websockets abandoned, Reverb migration planned).
10. **APP_DEBUG** — production mein `false` rakhna (abhi `true` hai — BUG-024).

## 6. Performance Rules

1. **Eager loading mandatory** — relationships access karne par `->with(['rel'])` use karo. ⚠️ Project mein abhi ZERO eager loading hai (BUG-025) — naya code yahi galti repeat mat karo:
   ```php
   // ❌ N+1 (project pattern — avoid)
   $bookings = Booking::all();
   foreach ($bookings as $b) { echo $b->guest->name; }
   // ✅
   $bookings = Booking::with('guest')->get();
   ```
2. **`Model::all()` mat use karo** bade tables par — `paginate()` / `limit()` / filtered queries use karo. `TravelAgent::all()` jaisi master-data calls ko `Cache::remember` karo.
3. **Caching** — expensive master data (revenue codes, room lists, travel agents) ko cache karo. Project mein sirf 2 cache usages hain — improve karo.
4. **Nested loops mein queries mat chalao** — collection operations / single query + groupBy use karo.
5. **Large exports (Excel/PDF)** — chunked processing use karo, timeout se bachne ke liye.
6. **Queues** — heavy work (email, PDF, webhooks) ko job mein daalo (project abhi `sync` hai — production mein Redis queue + workers).

## 7. UI / Blade Rules

1. **Escape output** — `{{ }}` default; `{!! !!}` sirf sanitized content ke liye (section 5.1).
2. **Inline JSON in `<script>`** — `{!! json_encode($data) !!}` safe pattern use karo, raw session data inject mat karo (violation SEC-05: `header.blade.php:670,768`).
3. **Consistent components** — existing design language (Bootstrap/jQuery) follow karo; naya CSS framework randomly introduce mat karo.
4. **Accessibility** — forms par labels, buttons par text, images par alt.
5. **No broken URLs** — routes/links hamesha named routes ya verified paths se.

---

## 8. Testing Rules

1. **Har feature/bug-fix ke saath tests** — at least unit test (logic) + feature test (route/endpoint) add karo.
2. **Baseline**: `php artisan test` → 26 tests green rehna chahiye. Tests todna = rejection.
3. **Test database**: `phpunit.xml` SQLite `:memory:` + array cache use karta hai — tests database-independent likho (hardcoded MySQL-specific SQL tests mein mat dalo).
4. **Edge cases test karo** — empty input, null, invalid dates, duplicate records, large numbers.
5. **Security tests**: XSS escaping, validation failures ke tests add karo jahan user input ho.

## 9. Before-Submit Review Checklist (Har Change)

- [ ] Kya maine related files padh li? (rules 1.1)
- [ ] Kya business logic preserve hai?
- [ ] Kya validation hai? (na ho to kyun?)
- [ ] Kya XSS safe hai? (`{!! !!}` kahin nahi user input par)
- [ ] Kya SQL injection safe hai? (raw SQL mein bindings?)
- [ ] Kya N+1 nahi hai? (`->with()` used jahan relationships)
- [ ] Kya `$fillable` respected hai? (`$request->all()` direct create nahi)
- [ ] Kya tests added + `php artisan test` green?
- [ ] Kya `composer audit` clean (agar dependencies change hui)?
- [ ] Kya debug leftovers (`dd`/`dump`/commented code) nahi hain?
- [ ] Kya CHANGELOG + memory updated?
- [ ] Kya naya dependency add hui to status check kiya? (abandoned nahi)

> **Sab checkboxes ✅ = ready. Koi bhi ❌ = incomplete.**

## 10. Hard Bans (Kabhi Mat Karna)

| ❌ Banned | Kyun |
|----------|------|
| `{!! $userInput !!}` in Blade | Stored XSS (SEC-03 violation already exists) |
| `DB::raw("...'{$userInput}'...")` / input concatenation | SQL injection |
| `Model::create($request->all())` | Mass assignment |
| `protected $guarded = [];` | Mass assignment |
| `dd()` / `dump()` / `var_dump()` in committed code | Debug leak |
| `chmod 777` | Permissions vulnerability (SEC-08) |
| `DROP TABLE` / `TRUNCATE` without confirmation | Data loss |
| Adding abandoned packages (`beyondcode/*`) | Security/maintenance risk |
| God-controller mein naya feature (CompanyController etc.) | Maintainability (BUG-025) |
| Hardcoded credentials / secrets in code | Secret leak |
| `composer update` without `composer audit` after | New CVEs undetected |
